# Core research methods release (FEAT-13)

The planning authority is `Feature Tasks` FEAT-13 and `Task Hierarchy` MAJOR-08 in the UTP Google Sheet. This release extends the original V1 scope explicitly; it does not change the status of existing V1 tasks. Production exposure remains gated by FEAT-13.07 and MAJOR-A/B/C proof.

The retained baseline is a target-backed usability test. Existing `test_versions`, `tasks`, `sessions`, `answers`, findings and reports stay readable. `test_versions.study_mode` defaults to `usability`; new `methods` versions can publish survey, open/closed card sorting and tree testing without a prototype target. `mixed` is reserved for versions containing both target-backed tasks and method blocks. The builder stores an ordered `study_blocks` snapshot. Published blocks cannot change; editing creates a new draft and copies blocks to the new version. Every `study_responses` row references a block and a session from the same workspace and exact test version, and one session can submit each block once.

Researcher input is validated by the shared TypeScript study contract before saving. Survey questions support single/multiple choice, integer scale, text, required/optional fields and a condition on an earlier single-choice answer. Card sort supports fixed published categories (`closed`) and participant-named categories (`open`). Tree tests store a rooted tree and destinations; the participant payload must omit the correct destination. The server validates responses against the published config before persistence. Incomplete or invalid responses must not be counted.

Researcher access follows workspace membership and editor roles. Raw method responses are sensitive evidence: authenticated researchers can read them only within a permitted workspace, and only server-side operations can insert them. Anonymous clients receive no direct table grant. Participant consent remains required before any response is collected. Invitation metadata and one-way token hashes live in `study_invites`, separate from anonymous behavioral responses. Researchers distribute one-use links themselves; the raw token appears only once in the URL fragment and is not stored. Expired, used, revoked and screener-rejected links cannot start another session. The older anonymous-session RPC rejects method studies so it cannot bypass the invite or screener gate. Deleting a session cascades its method responses and cited method evidence.

Results must derive from version-bound response rows. Survey distributions, card groupings/similarity, and tree success/path/directness have explicit sample denominators and response IDs. No eligible response is displayed as No Data, never as numeric zero. Findings may attach exact method responses; reports synthesize those findings. Retest comparison requires the same test and an earlier version, and compares only method blocks with identical ordinal, kind and config. Different cohorts are shown descriptively, without automatic causal claims.

The first release excludes AI, screen recording, native apps, paid panel operations and platform email sending. The `mixed` study mode is reserved in the schema but the methods-only runner is the supported new path for this increment. Production activation requires a migration dry run, RLS checks, authenticated researcher Preview smoke tests and the release gate in FEAT-13.07.
